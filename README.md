# Skincare Customer Sentiment and Review Theme Analysis

## Project Overview

This project analyses customer reviews of skincare products using Python. It aims to understand customer satisfaction, ratings, feedback patterns and recommendation behaviour through exploratory data analysis, data preprocessing, feature engineering and predictive modeling.

**Status:** Updated prototype using a real Sephora customer review dataset, with exploratory analysis and predictive modeling.

## Business Problem

Star ratings show how customers rate skincare products, but they do not fully explain why customers like or dislike them. This project explores ratings and written reviews to identify customer opinions, satisfaction levels, common feedback patterns and factors associated with product recommendations.

## Research Questions

1. What is the distribution of customer ratings?
2. Which brands receive the most reviews?
3. What are the most common words in customer reviews?
4. What proportion of reviews are positive, neutral and negative based on ratings?
5. What patterns can be identified from customer feedback?
6. Can customer recommendation behaviour be predicted using review text and selected product/customer attributes?

## Dataset

The project uses a 10,000-review sample from the [Sephora Products and Skincare Reviews dataset](https://www.kaggle.com/datasets/nadyinky/sephora-products-and-skincare-reviews).

**Original dataset file:** `sephora_skincare_reviews_sample.csv`

The original sample contains 10,000 records and 18 columns.

### Important Features

- `submission_time`: Review date
- `skin_type`: Customer skin type

## Sentiment Classification

Sentiment is initially classified using customer ratings:

- **4–5 stars:** Positive
- **3 stars:** Neutral
- **1–2 stars:** Negative

These are rating-based sentiment labels, not predictions from an AI text classifier. The actual meaning of written reviews may differ from their star ratings.

## Week 3: Data Cleaning and Preprocessing

A separate preprocessing pipeline has been introduced to prepare the Sephora review dataset for further analysis.

### Cleaning Operations

- Checks missing values in the dataset.
- Handles missing customer profile information by assigning an `Unknown` category.
- Converts relevant numeric columns into numeric format.
- Identifies invalid rating values and negative numeric values.
- Standardizes review text while preserving the original review text.
- Parses review submission dates.
- Removes exact duplicate rows.
- Creates rating-based sentiment labels.
- Generates a cleaning summary.

### New Files

- `data_cleaning.py` – Python script for data cleaning and preprocessing.
- `sephora_skincare_reviews_cleaned.csv` – Cleaned dataset generated by the pipeline.
- `cleaning_summary.csv` – Summary of missing values and cleaning operations.

**Note:** The preprocessing script removes exact duplicate rows. This is different from removing records based only on repeated review text.

## Week 5: Predictive Modeling and Algorithm Selection

Week 5 focuses on developing and comparing machine learning classification models to predict whether a customer recommends a skincare product.

### Objective

The objective is to predict the `is_recommended` target using cleaned review text and selected product/customer attributes.

The task is treated as a binary classification problem:

- **1:** Customer recommends the product.
- **0:** Customer does not recommend the product.

### Models Implemented

1. **Logistic Regression:** A classification algorithm used to estimate the probability of a customer recommending a product.
2. **Decision Tree Classifier:** A tree-based classification algorithm that learns decision rules from the input features.
3. **Majority Class Baseline:** A simple benchmark model that always predicts the most frequent class.

### Features Used

- Cleaned customer review text (`review_text_clean`)
- Skin type (`skin_type`)
- Brand name (`brand_name`)
- Product price (`price_usd`)

### Data Preprocessing

- TF-IDF vectorization was used to convert review text into numerical features.
- One-hot encoding was used for categorical features.
- Missing product prices were handled using median imputation.
- Numerical features were scaled.
- Rating and rating-derived sentiment fields were excluded to avoid target leakage.

### Dataset Used for Modeling

- Original records: 10,000
- Records with valid recommendation labels: 9,608
- Records excluded due to missing or invalid target values: 392
- Recommended reviews: 7,514
- Not-recommended reviews: 2,094
- Training records: 7,686
- Testing records: 1,922

### Model Evaluation Results

The models were evaluated on the same held-out test dataset.

| Metric | Logistic Regression | Decision Tree | Majority Baseline |
|---|---:|---:|---:|
| Accuracy | 88.14% | 66.13% | 78.20% |
| Macro Precision | 82.00% | 65.69% | 39.10% |
| Macro Recall | 85.70% | 73.01% | 50.00% |
| Macro F1 | 83.59% | 63.02% | 43.88% |
| ROC-AUC | 93.84% | 78.27% | 50.00% |

### Model Validation

- Stratified 80:20 train-test split.
- 3-fold stratified cross-validation on the training dataset.
- Random state: 42.

**Cross-validation Macro F1 results:**

- Logistic Regression: 82.61% ± 0.72%.
- Decision Tree: 61.67% ± 0.83%.

### Key Findings

Logistic Regression achieved the best overall performance:

- Accuracy: 88.14%.
- Macro F1-score: 83.59%.
- ROC-AUC: 93.84%.

It performed better than the Decision Tree and Majority Class Baseline in the overall evaluation.

Therefore, Logistic Regression was selected as the preferred model for further evaluation.

### Business Applications

The predictive model can help beauty and skincare businesses:

- Identify reviews that indicate customers may not recommend a product.
- Prioritise customer feedback for further investigation.
- Understand customer recommendation behaviour.
- Support product feedback monitoring.
- Identify patterns across brands, skin types and product prices.

Predictions are intended to support customer feedback analysis and should not replace human judgement or clinical product-suitability assessments.

## How to Run

### 1. Clone the Repository

```bash
git clone https://github.com/Pranavvvv123/skincare-customer-sentiment-analysis.git
```

### 2. Open the Project Folder

```bash
cd skincare-customer-sentiment-analysis
```

### 3. Install Required Libraries

```bash
pip install -r requirements.txt
```

### 4. Run Data Cleaning and Preprocessing

```bash
python data_cleaning.py
```

This generates:

- `sephora_skincare_reviews_cleaned.csv`
- `cleaning_summary.csv`

### 5. Run Exploratory Data Analysis

```bash
python week4_eda.py
```

The EDA script uses `sephora_skincare_reviews_cleaned.csv` if it is available in the same folder. Otherwise, it uses the original sample dataset.

The script generates:

- EDA summary
- Missing-value profile
- Feature-engineered dataset
- Eight visualization files

### 6. Run Predictive Modeling

Make sure `sephora_skincare_reviews_cleaned.csv` is present in the main project folder.

Run the following command from the main project folder:

```bash
python week5_modeling/week5_modeling.py
```

The modeling script generates:

- Model comparison results.
- Test predictions.
- Dataset summary.
- Logistic Regression confusion matrix.
- Decision Tree confusion matrix.

### 7. Run the Original Analysis

```bash
python analysis.py
```

Make sure the original sample dataset is present in the project folder before running the script.

## Limitations and Ethics

- The analysis uses a 10,000-review sample, not the complete dataset.
- The sample is a convenience sample and may not represent all Sephora customers.
- Rating-based sentiment may not always match the actual meaning of review text.
- Customer reviews may contain personal opinions and biases.
- Reviews are opinions and not clinical evidence of product safety or effectiveness.
- Missing customer information may affect certain comparisons.
- Correlation does not establish cause and effect.
- The recommendation target is imbalanced, which can affect classification performance.
- Predictive results depend on the selected dataset, features and model settings.
- The predictive model does not establish clinical effectiveness or individual product suitability.
- Dataset usage must follow its applicable licence and terms.
